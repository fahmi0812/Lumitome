## 0.3.50 — Skill baru latency-optimization

- Akar masalah: tidak ada skill umum di Lumitome untuk optimasi latensi jalur kritis. Yang paling dekat: `systematic-debugging` (cari akar masalah bug/tes gagal, bukan kecepatan) dan `performance-optimization` (khusus game, pack gamedev). Metode ini terbukti di sebuah event-driven bot handler: latensi internal 15–40 ms → di bawah 0,5 ms sebelum request terkirim (33 tes waktu lolos) — temuan-temuannya layak jadi skill yang bisa dipakai ulang, bukan sekadar perbaikan satu kasus.
- Perbaikan: skill baru `.opencode/skills/latency-optimization/SKILL.md` (sektor coding), metode UMUM untuk sistem event-driven apa pun (bot, webhook, API handler, game loop, notifikasi real-time). Workflow berurutan: (1) ukur hot path dulu dan catat baseline; (2) inventaris semua yang terjadi sebelum aksi kritis; (3) pindah semua I/O (tulis disk, print flush, notifikasi) ke setelah aksi terkirim; (4) scan payload sekali saja; (5) kirim raw request ganti wrapper berlapis; (6) dedup pakai ID stabil dari event, jangan pernah pakai hasil parse (placeholder hasil parse yang gagal tidak boleh disimpan sebagai "sudah dilihat"); (7) precompile regex + enkripsi native + event loop cepat; (8) pantau event edit, bukan hanya event baru; (9) notifikasi fire-and-forget, jangan subprocess blocking; (10) longgarkan deteksi event (jangan syarat frasa rapuh); (11) verifikasi dengan tes waktu. Guardrails: tanpa disk I/O/print/notifikasi blocking sebelum aksi kritis; tanpa dedup hasil parse; tanpa klaim optimal tanpa angka ukur. Didaftarkan lewat jalur standar: `gen-registry.mjs` (registry 900 → 901 skill, folder aktif 127 → 128) + `skills:index` (indeks aktif 734 → 735) + `gen-policy.mjs` (satu baris allow di agent sektor coding). Skill terverifikasi ter-route: query "handler lambat, kalah cepat sepersekian detik, latency tinggi" → latency-optimization peringkat 1 dan terpilih.
- Penyimpangan dari rencana, dicatat jujur: (a) Validate menuntut `src` + `sha` untuk skill aktif — frontmatter memakai `swanwright_sha` = HEAD saat skill ditulis (7db8a1a, v0.3.49), mengikuti konvensi skill lokal lain (docs-pack/stitch-ui memakai SHA commit repo saat ditulis). (b) Dua pin hitungan di suite-routing diperbarui ke angka baru yang sah (indeks aktif 734 → 735, folder aktif 127 → 128) — bukan dilemahkan, asersi tetap eksak. (c) Dua kegagalan awal tes baru adalah kesalahan redaksi tes sendiri (kata "claim" di SKILL.md melanggar tes "tanpa kata claim" — dua kalimat ditulis ulang tanpa kata itu, bukan tesnya yang dilonggarkan).
